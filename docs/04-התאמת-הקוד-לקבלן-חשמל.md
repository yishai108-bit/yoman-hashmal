# התאמת הקוד הקיים ל«יומן חשמל» (S.E.E)

**בסיס:** `קוד/yoman-v55-חי-עין-תמר.html` (גרסה 55, 29.10.2026). הריפו `קוד/ריפו-yoman-atar/` הוא גרסה 52 עם אותו מבנה; `src/` מפוצל לפי נושא ו-`tools/build.js` משרשר אותו לקובץ אחד לפי `src/order.txt`. שלב ראשון בפרויקט החדש: לסנכרן את `src/` לגרסה 55 כך שהבנייה זהה.

- `src/body.html`: לשוניות חדשות: **ביצוע · מלאי · כבלים · ניפוקים · יומיות · כתב כמויות**. להסיר את לשוניות בטון ופאנלים ואת כל הגיליונות שלהן. כותרת: `<b>S.E.E</b><שם אתר>`.
- `src/style.css`: ללא שינוי בגרסה 1 (אפשר להחליף צבע מותג אחד).
- `src/order.txt`: להסיר 02, 03, 04, 05, 14, 17; להוסיף `js/19-cables.js` אחרי 13.

## 3. בנייה, אתרים, בדיקות

- `src/sites.json`: רשומה אחת: `"see-<אתר>": {"title": "יומן חשמל · <אתר>", "name": "S.E.E · <אתר>"}`.
- `tools/build.js`: `BASE.title` ו-`BASE.name` חייבים להתאים למחרוזות החדשות ב-`head.html` / `body.html` / `core.js`, אחרת `forSite` זורק שגיאה. זה בכוונה.
- `tests/fixture.js`: נתונים סינתטיים בלבד. להסיר פאנלים / בטון, להוסיף תופים ומשיכות.
- `tests/*.test.js`: `calc` (מלאי, מאזן כבלים), `flows` (תעודה → תוף → משיכה → סגירה; ניפוק עם חתימה; ספירה), `issue-pdf`, `net` («אין חיבור»), `settings-merge` (שמירה בלי דריסה), `build` (זהות הבנייה), `smoke` (רינדור 400px).
- `.github/workflows/tests.yml`: נשאר; רץ בכל push ויומית.
- `npm test` ירוק = מותר לפרסם. אדום = לא.

## 4. מודל הנתונים: מה משתנה

| אוסף / מסמך | היה | ל«יומן חשמל» |
|---|---|---|
| `deliveries` | שורות עם `cat` construction / electrical | `cat`: cables / install / consumables / tools; שורה עם `drumNo` יוצרת `drums` |
| `issues` | ניפוקי ברגים לקבלן | ניפוקי חומרים (כל פריט) |
| `moves` | הוצאות / ניפוקי ציוד | ללא שינוי |
| `concrete`, `panels`, `panelbal`, `panelmoves` | | **לא קיימים** |
| `settings/bom`, `settings/cba` | | **לא קיימים** |
| `settings/boq` | EBOQ של חשמל | כתב הכמויות של הקבלן (אותו מבנה: code, name, qty, unit, group) |
| **חדש** `drums` | | drumNo, cableType, lengthIn, deliveryId, location, status, closedAt, remainderAtClose |
| **חדש** `pulls` | | date, drumId, meters, area, ref, crew, by |
| **חדש** `settings/cableTypes` | | code, desc, section, conductor, color, boqCode, aliases[] |

כללי חישוב (פונקציה אחת): `arrived` רק מתעודות; `cableArrived = Σ drums.lengthIn`; `cablePulled = Σ pulls.meters`; `cableStock = arrived − pulled`; `remainderAtClose = lengthIn − Σ pulls` לתוף.

## 5. פרסום מופע ל-S.E.E

1. בניית `dist/see-<אתר>.html` (`npm run build:sites`).
2. פרסום כ-artifact **חדש ופרטי**, **מהפרויקט החדש**, עם `capabilities.json` במפורש (sample, assets, downloads, user profile, db עם כללי קריאה / כתיבה / בעלים להגדרות).
3. בדיקה בטלפון: לשוניות, קליטת תעודה עם צילום, משיכת כבל, ניפוק עם חתימה, גיבוי.
4. «התחל מאתר ריק» → הגדרות אתר → ייבוא כתב כמויות וסוגי כבלים → צוות → ספירת תופים פתיחה.
5. Share → הזמנה במייל למשתמש של S.E.E עם Can edit. המשתמש נכנס עם חשבון Claude באותו מייל. **לבדוק את זה על מופע ריק לפני כל דבר אחר.**
6. בפרסום חוזר ההרשאות נשמרות. בכל גרסה: `APP_VERSION` עולה, גיבוי של הקודמת, הודעה למשתמש מה השתנה.

## 6. מה לא מעבירים לעולם למופע של S.E.E

- נתונים של המעסיק של ישי: תעודות, כתבי כמויות, מחירים, ספקים, רשימות עובדים, צילומים, גיבויים, `seed.json`.
- כינויים נלמדים (`settings/aliases`) מהמופעים הקיימים. הם נבנו על ספקים ופריטים של אתר אחר; S.E.E ילמדו את שלהם תוך שבועיים.
